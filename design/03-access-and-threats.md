# 03 权限模型与威胁清单

对应流程第 3 步「身份与权限」。

## 身份

- 用户必须登录才能提问。第一期支持 GitHub OAuth 登录和邮箱验证码登录。
- 身份字段：`user_id`（系统内部生成的假名编号）、`auth_provider`（`github` 或 `email`）、`role`、`created_at`。邮箱和 GitHub 用户名只存在账号表里，不进日志。
- 网页会话是服务端签发的 JWT，细则见下面的「会话 JWT」。OAuth 密钥和 JWT 签名密钥从环境变量读取，不写进代码或配置文件。
- 不划分租户。所有用户看到的是同一套公开知识。
- 第一期的管理员只来自环境变量里的身份名单，名单不进仓库。GitHub 登录对数字用户编号，邮箱登录对已经验证的邮箱。对上的人这一次会话是管理员，对不上的是普通用户。判定结果写入会话 JWT 的 `role`。名单为空时没有管理员，普通用户仍可提问。名单里放两个项目作者自己的身份，避免单一登录方式失效后进不了管理功能。第一期不在网页上把别人提升为管理员。审核由管理员兼任。

## 会话 JWT

网页登录成功后签发一张 JWT，放在名为 `__Host-eb_session` 的 Cookie 中。属性为 `Secure`、`HttpOnly`、`SameSite=Strict`、`Path=/`。不设 `Domain`，也不设 `Max-Age`。浏览器脚本读不到令牌正文。查询 API 不接受这张令牌，也不接受这个 Cookie。

签名只用 `HS256`。签名密钥为 32 字节，用密码学随机数生成，放在环境变量 `JWT_SIGNING_KEY`。校验时只接受 `HS256`，拒绝 `alg=none`。不使用令牌头里的 `jku`、`jwk`、`x5u`、`x5c` 选择密钥。

头里的 `typ` 必须是 `elderbrain-session+jwt`。下列声明缺一不可：

| 声明 | 要求 |
| --- | --- |
| `iss` | 必须等于 `elderbrain` |
| `aud` | 必须等于 `elderbrain-web` |
| `sub` | 内部 `user_id` |
| `role` | `user` 或 `admin` |
| `iat`、`nbf`、`exp` | 签发、生效、过期时间。绝对有效期 8 小时。校验允许 60 秒时钟偏差 |
| `jti` | 密码学随机数，至少 128 位 |

令牌里不放邮箱、GitHub 用户名或其他个人信息。

第一期不签发刷新令牌，到期后重新登录。登出时把 `jti` 写入拒绝名单，保留到该令牌的 `exp`。名单只存 `jti` 和过期时间，不存令牌原文，也不并入 90 天审计。已在名单中的 `jti` 返回 401。只删除 Cookie 不算登出完成。第一期不做按空闲时间作废会话。

管理员名单在签发时写入 `role`。名单变更不追溯已发出的令牌，最迟在 8 小时有效期结束时生效。

## 角色与权限

知识内容全部公开，所以权限只控制功能，不控制文档。

| 功能 | 用户 | 审核员 | 管理员 |
| --- | --- | --- | --- |
| 提问、查看引用原文 | 是 | 是 | 是 |
| 提交反馈（好评、差评、备注） | 是 | 是 | 是 |
| 查看并处理审核队列 | 否 | 是 | 是 |
| 审核术语表条目 | 否 | 是 | 是 |
| 接入或停用来源、重建索引 | 否 | 否 | 是 |
| 发布或回退索引、提示词、模型版本 | 否 | 否 | 是 |
| 查看请求日志 | 否 | 仅限审核队列关联的请求 | 是 |
| 调整配额与全站成本上限 | 否 | 否 | 是 |
| 创建或吊销自己的 API 密钥、删除自己的对话 | 是 | 是 | 是 |

审核员只能看到与审核队列关联的请求，避免浏览其他用户的全部提问。

## 查询 API

第一期同时提供网页和可供外部调用的查询 API。两者遵守同一份回答契约。

- 用户在网页的登录会话里创建可吊销的 API 密钥。密钥只在创建时完整显示一次，数据库只存哈希。
- 每个用户同时有效的密钥最多 2 把。要创建新的，先吊销一把。吊销立即生效。这个上限做成可配置项，以后可以改。
- 查询 API 只接受密钥，不接受会话 JWT，也不接受浏览器 Cookie。没有免登录调用。
- 网页和 API 共用该账号的每日次数、每分钟次数，以及全站费用上限。
- 密钥只能替该用户提问，以及延续他自己的对话。`conversation_id` 不属于该用户时返回 403。
- 创建密钥、吊销密钥、删除对话、查看审计、调整配额，只在网页的登录会话里做。吊销密钥后，已有对话存档还在，只是这把密钥不能再调用。

## 检索条件

- 规则版本只过滤 `5.1`。它是检索条件，不是权限。问 5.2 时在检索前拒答。
- 来源状态是检索时的过滤条件：已停用的来源立即不再参与检索，见 [02-sources.md](02-sources.md) 的下架流程。
- 两个条件都在向量检索时过滤，不在检索之后再筛。

## 配额

| 项 | 第一期取值 | 说明 |
| --- | --- | --- |
| 每账号每日提问次数 | 100 | 拒答也计数，防止用无关请求消耗资源 |
| 每账号每分钟提问次数 | 10 | 防止脚本刷接口 |
| 全站每日 token 上限 | 按月成本目标折算，见 [08-operations.md](08-operations.md) | 达到上限后暂停新提问并告警 |
| 新账号首日次数 | 20 | 降低批量注册滥用的收益 |
| 空问题或超长问题 | 不占每日次数，也不占每分钟次数 | 返回 422，不调用嵌入和生成。见下面的问题长度 |

## 失败即关闭

- 会话 JWT 无效、过期或已登出，或 API 密钥无效：返回 401，不降级为匿名访问。
- 配额耗尽或达到全站上限：返回 429，告知恢复时间，不排队。网页和 API 计在同一套配额里。
- 角色校验失败，或 `conversation_id` 不属于当前用户：返回 403。
- 版本或来源过滤条件构造失败：拒绝本次请求，不在无过滤的情况下检索。
- 过滤后没有候选，或重排后没有父节达到分数下限：按「证据不足」拒答，不调用生成模型，也不改用模型自身的记忆。
- 空问题或超长问题：返回 422，不截断，不调用嵌入和生成，不占每日次数和每分钟次数。

## 问题长度

两道闸都超限时返回 422，并说明是哪一道。不截断问题，以免检索只看见前半段。

- **请求体上限：** 可配置。在解析之前拒绝空问题和超大包，用来挡滥用。今天不写死字符数。
- **嵌入输入上限：** 等嵌入模型选定后，按该模型文档里的单条输入上限拒绝。若厂商会在查询前自动加一段固定提示，用户文本的上限要扣掉这段。

审计只记拒绝原因和长度，不记问题全文。

## 威胁清单

| 威胁 | 例子 | 由哪一层挡住 | 分期 |
| --- | --- | --- | --- |
| 被当作免费大模型接口滥用 | 让系统写代码、翻译长文、闲聊 | 服务层输入检查按「与规则无关」拒答，并计入配额；控制层全站成本上限 | 第一期 |
| 批量注册刷配额 | 脚本注册大量邮箱账号 | 新账号首日低配额；邮箱验证码频率限制；按 IP 限制注册频率 | 第一期 |
| 用户输入中的提示注入 | 「忽略之前的指令」「输出系统提示词」 | 服务层输入检查；提示词中把用户输入和知识片段明确隔开 | 第一期基本检查，第三期完整护栏 |
| 知识片段中夹带指令 | 上游仓库被改写，加入指令性文字 | 来源固定到提交号或校验值；只有管理员能接入来源；入库时扫描指令性文字 | 第一期 |
| 知识源投毒 | 篡改中文译文中的数值 | 固定到提交号；抽查中文数值；引用校验对比中文原文；异常进入审核队列 | 第一期 |
| 系统提示词泄露 | 诱导模型复述提示词 | 输入检查拦截；提示词里不放密钥和内部地址 | 第一期；影响低，可接受 |
| 回答里带出个人信息 | 用户把队友信息写进问题 | 知识库不含个人信息；日志脱敏 | 第一期 |
| 现实政治内容 | 借阵营体系评论现实人物 | 输入检查按「现实政治」拒答 | 第一期 |
| 审核员越权浏览日志 | 审核员查看与队列无关的提问 | 日志查询按审核队列关联关系过滤 | 第二期（审核队列上线时） |
| 页面脚本读出会话令牌 | 注入脚本读取浏览器里保存的 JWT | 令牌只放在 `HttpOnly` Cookie 中，页面不把 JWT 交给脚本 | 第一期 |

## 前端与接口安全提醒

- 回答和引用原文按纯文本或经过消毒的 Markdown 渲染，不直接写入 HTML，防止知识片段或用户输入造成 XSS。
- 写操作接口（反馈、审核、管理，以及会消耗配额的提问）要做 CSRF 防护。会话 Cookie 的 `SameSite=Strict` 是附加约束。
- 所有接口参数都要做类型和范围校验。问题长度按上面的两道闸，版本取值只能是 `5.1`。
- 数据库访问一律使用参数化查询。
